# 架構與維護性改善工作清單

開發基準：`origin/develop`（遵循 README 的貢獻規範）。改動保留現有 Tauri command、事件與進度檔格式。

## 工作原則與需求來源

使用者的需求是改善架構、可維護性與效能，並依「質疑需求 → 刪除 → 簡化與優化 → 縮短週期 → 最後自動化」執行。本清單的技術方案由實作者提出，必須有程式碼中的問題依據；拆模組、增加狀態機、版本協定或背景工作都不是預設的必要需求。

保留一項工作前，先說清楚它解決哪個可觀察問題、現有流程能否更小幅度修正，以及如何驗證。先刪除不必要的流程，再測量留下來的部分；自動檢查只覆蓋已確認需要的行為。

## 第一批：下載核心與前端狀態邊界

- [x] 將音訊、視訊共用的暫存檔與分片排程抽出，限制同時存活的分片工作數，避免整段影片一次建立全部工作。
- [x] 區分分片完成與中斷，讓重來、刪除和下載失敗不會誤標完成；傳遞工作 panic 與下載錯誤。
- [x] 驗證 HTTP Content-Range 與實際回傳長度，拒絕錯誤範圍或截短內容。
- [x] 暫存檔遺失或大小不同時重設分片狀態，避免沿用失效的斷點。
- [x] 將前端下載資料型別、事件更新、顯示計算與訂閱生命週期移出畫面元件。
- [x] 修正還原任務的顯示、零分片進度與未選取處理步驟；解除訂閱並取消待執行的畫面更新。
- [x] 補上核心回歸測試、可重複執行的測試命令與 CI。

## 第一批的模組邊界

| 模組                                      | 責任                                           |
| ----------------------------------------- | ---------------------------------------------- |
| `downloader/media_download.rs`            | 共用暫存檔、斷點有效性及分片完成更新           |
| `downloader/chunk_transfer.rs`            | 有界工作排程、錯誤與中斷傳遞；不依賴 Tauri     |
| `downloader/http_range.rs`                | HTTP 範圍與長度驗證；不依賴 HTTP client        |
| `features/downloads/progress.ts`          | 依已完成的實際分片位元組數計算進度及步驟文字   |
| `features/downloads/events.ts`            | 按順序更新任務資料；不依賴 Vue 或 Tauri 執行期 |
| `features/downloads/session.ts`           | 訂閱、還原快照、重播期間事件及解除訂閱         |
| `features/downloads/useDownloadEvents.ts` | 將下載 session 接入 Vue 生命週期與 Tauri       |

分片排程保留原有全域 semaphore，額外限制每個媒體存活的工作數；排程額外資源隨並行上限成長，而非隨全部分片數成長。進度資料仍保留完整分片列表。下載失敗會停止新增工作並取消未完成工作，已確認完成的分片仍可續傳。

這一批沒有改動進度檔格式、Tauri command 或事件格式，也沒有量測實際下載速度。高頻快照、同步磁碟寫入及任務狀態競態仍列於後續工作。

## 第二批：縮小進度儲存與還原流程

| 保留的工作               | 問題依據                                                    |
| ------------------------ | ----------------------------------------------------------- |
| 原子替換進度檔           | 原本直接覆寫 JSON，寫入中斷可能破壞上次可還原的進度         |
| 儲存、刪除共用順序控制   | 檢查檔案存在與寫入若分開，刪除後的更新可能重新建立檔案      |
| 縮小進度鎖範圍           | 原本回傳鎖 guard，導致事件序列化與磁碟 I/O 期間持續阻擋讀取 |
| 重複還原使用現存任務     | 原本取消現存任務，再用磁碟上的舊快照取代                    |
| 保留無法解析及無關的檔案 | 原本還原流程會直接刪除，讓問題無法檢查或修復                |

- [x] 將檔案操作集中於不依賴 Tauri 的 `downloader/progress_store.rs`，維持既有 JSON 格式與儲存時機。
- [x] 事件發送和寫檔移出進度讀寫鎖；更新順序由較小的發布鎖維持。
- [x] 使用同目錄暫存檔與原子替換，序列化失敗時保留正式檔案。
- [x] 以單一路徑協調寫入與刪除，拒絕刪除後的延遲更新；刪除通知不再有刪檔後失敗的回滾缺口。
- [x] 還原改為一次 `spawn_blocking`，逐檔讀取與解析，移除每個檔案一個工作及額外 Rayon 管線；重複還原沿用現存任務。建立任務時維持註冊順序，避免同時還原產生第二份任務。
- [x] 刪除因此不再需要的取消通道，以及只輸出 NFO 的型別上未使用的 XML 反序列化實作。
- [x] 驗證檔案格式、寫入失敗保護、刪除競態與還原行為。

刪除的自訂方案：進度檔版本協定、常駐寫入執行緒、待寫入快照佇列、計時合併、重試排程與退出刷新。現階段缺少遷移需求或效能數據來支持這些成本。同步儲存仍然存在，先量測序列化時間、鎖等待與寫入量，再判斷是否需要批次寫入。

`tempfile` 已存在於鎖檔，改為直接使用其跨平台原子替換功能，以免自行維護 Windows／Unix 的暫存檔與重新命名細節。

## 測試命令

前端測試使用 Node.js 內建測試工具與 TypeScript 型別移除功能；依賴更新後統一使用 Node.js 24 或更新版本，沒有新增測試套件。

```sh
pnpm install --frozen-lockfile
pnpm test:frontend
pnpm test:backend
pnpm check
pnpm build
```

`pnpm test` 會依序執行前、後端測試。Rust 單元測試需要 Tauri 的平台建置依賴；前端邏輯測試可獨立執行。

## 驗收

第一批需通過前端格式、ESLint、TypeScript、正式建置與單元測試，以及 Rust 格式、Clippy 與單元測試。測試不依賴 Bilibili 帳號或外部 CDN。真實登入、下載及桌面互動仍需另外驗證。

驗收涵蓋 21 個前端測試、29 個 Rust 核心測試與 1 個插件測試；三個 Rust workspace 的格式與零警告 Clippy、ESLint、TypeScript、Prettier、前端正式建置及所有 workflow 的 actionlint 一併檢查。XML 巨集的相容性警告已修正，沒有關閉該警告。

三次獨立程序的 JSON 解碼微基準，配對加速比中位數為 1.60–1.71×，原始樣本與限制見 [量測記錄](benchmarks/2026-11-19/README.md)。前端建置仍會提示既有的單一 JavaScript bundle 大於 500 kB，是否拆包待效能量測後決定。
