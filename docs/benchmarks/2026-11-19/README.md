# JSON 解碼微基準：2026-11-19

此比較只測量 CPU 上的 API JSON 解碼，排除網路、磁碟與 GUI。三次獨立程序都先檢查新舊輸出相等，再預熱及交替執行 30 組量測。完整樣本及各次程序的配對比值 bootstrap 區間保留於同目錄 JSON。

環境：Windows x86_64、AMD Ryzen 7 4800H、Rust 1.100.0。使用 `cargo bench` 最佳化 profile（opt-level=3、lto=false、codegen-units=16）。完成編譯後依序執行三個程序，未同時進行其他編譯；沒有隔離系統背景活動。

| 輸入筆數 | 舊流程中位數範圍（μs） | 新流程中位數範圍（μs） | 各次配對加速比中位數 |
| -------- | ---------------------- | ---------------------- | -------------------- |
| 20       | 18.05–18.65            | 10.65–10.78            | 1.69–1.71×           |
| 200      | 212.83–219.49          | 131.27–140.06          | 1.60–1.65×           |
| 2000     | 1856.53–1910.17        | 1103.88–1124.10        | 1.68–1.70×           |

範圍是三次程序各自的中位數最小／最大值，不是跨程序信賴區間。JSON 中的 95% bootstrap 區間只描述各次程序內的配對樣本。這些結果支持移除中間 JSON 字串與成功路徑錯誤配置；它們不能證明整體下載吞吐量、UI 速度或其他硬體上的改善。

重現方式：在專案根目錄建立輸出目錄，將 `BENCH_OUTPUT` 設為該目錄中一個 JSON 檔的絕對路徑，再執行 `pnpm benchmark`；更換輸出檔名並重複三次。未納入前一份與其他編譯同時執行的探索量測。
